# HH Monitor

Система мониторинга рынка труда на основе API hh.ru: сбор вакансий, живой дашборд,
финальные недельные отчёты. Конфигурируется под любую профессию — от поддержки до разработки.

## Архитектура

- `collector.py` — сбор вакансий (cron, ежедневно 8:00–20:00). Ходит в hh API по фразам
  роль-групп, сохраняет новые вакансии в SQLite, дотягивает полные карточки
  (зарплата, навыки, опыт, формат работы).
- `mark_archived.py` — каждый час помечает вакансии, исчезнувшие из поиска (закрыты).
- `app.py` + `templates/dashboard.html` — живой веб-дашборд (Flask + SQLite), обновление каждый час.
- `weekly_report.py` — финальный недельный отчёт (`weekly.html`, cron воскресенье 20:05)
  и снапшоты недели в таблице `weekly_reports` для сравнений.
- `.env` — ключи hh API (client_id/secret, User-Agent) и доступ к дашборду.

## Как выбирать роли, чтобы результат был релевантным

Фильтрация двухуровневая.

**Уровень 1 — поисковые фразы (ROLE_GROUPS в collector.py).**
hh ищет фразу по всему тексту описания, а не только в названии. Поэтому сырая выдача
всегда содержит шум: вакансия разработчика, где в тексте упомянут искомый термин,
придёт в выборку. Фразы в кавычках = точное вхождение. Роль-группы делят рынок на
сегменты (например, «руководители» и «тимлиды»).

**Уровень 2 — титульные маркеры.**
Чтобы убрать шум, в KPI попадают только вакансии, у которых в НАЗВАНИИ есть целевые
маркеры профессии/уровня. Три набора маркеров:
- положительные — роль остаётся в KPI (сегмент, который мониторим);
- отрицательные — роль исключается из KPI;
- смежные — роль видна в отдельном наблюдательном блоке, но не разбавляет KPI.

Рецепт настройки под любую профессию:
1. выписать 5–10 поисковых фраз роли в ROLE_GROUPS;
2. задать маркеры титулов (положительные/отрицательные/смежные);
3. посмотреть недельную выборку глазами и добить маркеры по реальным названиям.

Без уровня 2 медианы раздуваются зарплатами соседних сегментов
(кейс экземпляра: «медиана 250K» оказалась руководителями ИТ-инфраструктуры,
попавшими в выдачу по тексту описания).

## Дашборд: что означает каждый блок

- **Новых сегодня** — вакансии за текущий день; бейдж — динамика к вчера.
- **За неделю (с пн)** — накопление текущей недели; неделя всегда стартует с понедельника.
- **Медиана «от» / «до» (неделя)** — медианы нижней и верхней границ вилок в рублях.
  Считаются по разным подмножествам: вакансия может публиковать только одну границу.
  Прочерк = за неделю ещё не пришло вакансий с этой границей (норма для начала недели),
  бейдж при этом показывает ориентир прошлой недели.
- **Итоги недели (к прошлой неделе)** — три строки (число вакансий, медиана «от»,
  медиана «до») с двумя бейджами: «к прошлой неделе» (против полного снапшота) и
  «к этому дню прошлой» (против такого же окна прошлой недели) — честная динамика
  в начале недели, когда накопление ещё маленькое.
- **Количество вакансий за день** — столбчатая диаграмма за 7 дней: активность публикации.
  Выходные видны отдельно.
- **Медианная зарплата по дням** — кривые «от» и «до» за 7 дней; дни без данных
  заполняются предыдущим значением (ffill), чтобы кривая не рвалась.
- **Новые сегодня / Новые за неделю** — списки вакансий с фильтрами по зарплате
  (только с вилкой, 100k+, 150k+, 200k+).
- **Опыт и навыки** — структура спроса; клик по чипу фильтрует список вакансий.
- **Топ компаний за неделю** — кто нанимает активнее.
- **Архив закрытых за неделю** — сколько вакансий закрылось (скорость найма рынка).
- **Вакансии за выходные** — наблюдательный блок: публикации сб/вс.
- **Смежные роли** — соседний сегмент (настраивается маркерами): виден, но не входит в KPI.
- **Топ-10 зарплат недели** — верхняя граница рынка.

## Неделя и финальный отчёт

- Дашборд копит текущую неделю с понедельника в реальном времени.
- Финальный отчёт (`weekly.html`) — за последнюю завершённую неделю пн–вс
  (включая выходные). Генерация — воскресенье 20:05; страница держится до следующего
  воскресенья. Ручной запуск в любой день пересобирает ту же завершённую неделю —
  подглядывать в «незакрытую» неделю нельзя и не нужно.
- Снапшоты недели пишутся в `weekly_reports` и используются для сравнений «к прошлой неделе».

## Принципы честных цифр

- Медианы «от» и «до» — разные подмножества; прочерк — это отсутствие данных, а не ошибка.
- В начале недели выборка мала и медиана волатильна — оценивать рынок по закрытой неделе.
- Смежные сегменты держим вне KPI, иначе медиана чужая.
- Сбор распределён по дню, чтобы не ловить rate-limit hh API (понедельничный «взрыв»
  запросов после выходных приводил к бану токена на полдня).

## Конфигурация текущего экземпляра (пример)

Роль-группы: `head_of_support`, `team_lead_support`, `it_head` (мониторинг рынка
руководителей поддержки; смежный сегмент — ИТ-руководители). Маркеры и фразы —
в `collector.py` и в запросах `app.py`/`weekly_report.py`.

## Стек

Python 3, SQLite, Flask, nginx, cron, VPS. API: hh.ru (OAuth client_credentials).
